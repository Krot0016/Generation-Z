# TwinBoost — генератор цифровых двойников цеха

Интерактивный **UI-прототип** (фронтенд-пустышка) сервиса для цехов
металлообработки. Никакого бэкенда: импорт файла, генерация, живые
показатели и заявка имитируются в браузере на моковых данных.

## Стек

- **React 18 + Vite 5**
- **Tailwind CSS 3**
- **Lucide React** — иконки
- Шрифты Inter + JetBrains Mono

## Запуск

```bash
cd twinboost
npm install
npm run dev
```

Vite откроет приложение на `http://localhost:5173` (или на следующем
свободном порту). Production-сборка:

```bash
npm run build
npm run preview
```

## Пользовательский путь

1. **Лендинг** — оффер, три кейса внедрений, профили предприятий.
2. **Импорт** (`Создать цифровой двойник`):
   - загрузка любого `.xlsx` / `.csv` или кнопка «Загрузить пример
     ведомости.xlsx» запускает имитацию анализа на 1,6 секунды;
   - результат сразу открывается с четырьмя предвыбранными станками;
   - альтернативный путь — «Выбрать» → ручная сборка.
3. **Ручная сборка**:
   - фильтры по виду, модели и году выпуска;
   - каталог из шести типовых станков, включая 16К20, 6Р12 и 3Г71
     с навесными датчиками;
   - один тип можно добавить несколько раз (`#1`, `#2`);
   - клик по добавленным карточкам строит маршрут с анимированными
     стрелками и этапами;
   - удаление станка, сброс порядка и генерация доступны сразу.
4. **Генерация** — 1,85 секунды имитации сборки паспортов и датчиков.
5. **Результат**:
   - плашка «Демо-режим» с количеством станков;
   - цепочка с карточками и живыми показателями (ток, температура,
     вибрация, загрузка), обновление каждые 2,4 секунды;
   - модальное окно заявки с валидацией и экраном успеха;
   - возврат в конструктор с сохранением конфигурации.

## Важно

- Файл **не читается** и не отправляется на сервер. Для любого файла
  подставляется встроенный демонстрационный набор.
- Заявка **никуда не отправляется** и не сохраняется.
- Все предприятия, показатели и кейсы вымышлены.
- Живые значения имитируются случайным блужданием вокруг базовых
  профилей станков на клиенте.

## Деплой на GitHub Pages

1. Создайте публичный репозиторий (без README и без .gitignore).
2. Откройте папку `github-upload` и перетащите **всё её содержимое** в раздел
   *Add file → Upload files* нового репозитория (включая `.github` и `.gitignore`,
   для этого в Проводнике включите «Показать скрытые элементы»).
3. Settings → Pages → Source: **GitHub Actions**.
4. Actions → workflow `Deploy website` → при необходимости **Re-run all jobs**.

Сайт будет доступен по адресу `https://<логин>.github.io/<имя-репозитория>/`.
`base: './'` в `vite.config.js` делает пути относительными, поэтому имя
репозитория может быть любым.
